# Development

## Layout

```
android/app/src/main/java/com/vrtrack/tracker/
  TrackingEngine.kt   CameraX → MediaPipe → pose/gaze → UDP; owns calibration
  TrackingService.kt  foreground service (camera type), wake lock, lock-screen notification
  NetworkClient.kt    UDP stream, broadcast discovery on every interface, ping/RTT, reconnect
  PoseMath.kt         MediaPipe 4×4 matrix → yaw/pitch/roll/x/y/z
  Calibration.kt      calibration wizard logic + profile
  Protocol.kt         wire format (mirrors pc/vrtrack/protocol.py)
  ui/                 Jetpack Compose screens: Track, Calibrate, Settings, Onboarding
pc/vrtrack/
  protocol.py receiver.py   packet parsing, dedupe, discovery/ping replies
  processing.py             dead zone/curve/sensitivity/invert + OutputStage (120 Hz interpolation)
  controller.py             UI-independent core (profiles, receiver, output, status)
  profiles.py settings.py   JSON profiles and app settings in ~/.vrtrack
  ui/                       PySide6 window (Dashboard, Tuning, Setup, About), theme, widgets
installer/                  Inno Setup script + build.ps1 (bundles the pinned OpenTrack release)
tools/                      make_icons.py, fetch_model.py, gen_vectors.py, set_version.py
```

## Run from source

**Desktop**

```bash
cd pc
python -m pip install -e ".[dev]"
python -m vrtrack            # GUI
python -m vrtrack --headless # console only
python -m pytest             # tests (UI tests run offscreen)
ruff check .
```

**Android** (JDK 17, Android SDK 35; Android Studio is optional)

```bash
python tools/fetch_model.py          # downloads face_landmarker.task (checksum-verified, not in git)
cd android
./gradlew testDebugUnitTest          # unit tests (incl. wire-format vectors shared with Python)
./gradlew assembleDebug              # app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

For debugging without tapping the phone: `adb shell am start -n com.vrtrack.tracker/.MainActivity --ez autostart true`
starts tracking (camera permission must already be granted).

## Tests

- **Desktop**: protocol round-trip and rejection, wrap-aware sequence numbers, receiver loopback (UDP discovery, ping,
  late/duplicate/lost counting, phone-restart recovery), dead zone/curve/invert, interpolation stage, controller,
  profiles, and an offscreen UI smoke test that builds every page and feeds it real packets.
- **Android**: wire format against `protocol/test_vectors.json`, pose maths (yaw recovery, scale invariance, degenerate
  matrices), gaze normalisation (never invents values when not measured).
- **Cross-language**: `protocol/test_vectors.json` is generated by `tools/gen_vectors.py`; both test suites assert
  byte-identical encoding. CI fails if the committed file is stale.

Not covered by automated tests (needs a camera and a game): head-pose accuracy, gaze quality, end-to-end latency.

## Icons

The master artwork is `assets/branding/icon-source.png`. After replacing it run:

```bash
python tools/make_icons.py            # regenerates Android mipmaps, desktop .ico/.png and installer images
```

## CI/CD

| Workflow | Trigger | What it does |
|---|---|---|
| `ci.yml` | push to `main`, pull requests | Desktop tests + lint on Ubuntu/Windows × Python 3.10/3.12; fixtures-up-to-date check; Android unit tests, lint and debug APK; Windows installer build (on push) |
| `release.yml` | tag `vX.Y.Z` (or manual run) | Tests, then builds the **Windows installer** (bundles OpenTrack), **Linux bundle** and **Android APK**, and publishes a GitHub Release with SHA-256 files |
| `dependabot.yml` | monthly | Updates for Actions, Gradle and pip dependencies |

### Making a release

```bash
git tag v0.2.0
git push origin v0.2.0
```

The workflow stamps the version into the desktop app (`tools/set_version.py`) and the APK (`-PversionName`,
`-PversionCode = major·10⁶ + minor·10³ + patch`), then attaches everything to the release. You can also run the *Release*
workflow manually from the Actions tab with a version number: it builds everything, creates the tag `vX.Y.Z` on the
current commit and publishes the release the same way. All three platform jobs must succeed before anything is published.

### Android signing

Without secrets, the release workflow publishes a **debug-signed** APK (it installs fine, but you can't update an app
signed with a different key). For a properly signed release create a keystore **once** and keep it safe:

```bash
keytool -genkeypair -v -keystore vrtrack-release.keystore -alias vrtrack \
  -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 vrtrack-release.keystore      # → ANDROID_KEYSTORE_BASE64
```

Add these repository secrets (Settings → Secrets and variables → Actions):
`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
Never commit the keystore (it is in `.gitignore`). Losing it means you can no longer update installed copies.

### Windows installer

`installer/build.ps1` does everything: it downloads the **pinned** OpenTrack setup from
`installer/opentrack.json` and verifies its SHA-256 (the build fails on mismatch), freezes the app with PyInstaller,
and compiles `installer/vrtrack.iss` with Inno Setup. Needs Python with `pip install -e "pc[dev]"` and Inno Setup 6
(preinstalled on GitHub's Windows runners).

```powershell
./installer/build.ps1          # → installer/build/out/VRTrack-Setup-<version>.exe
```

To bump OpenTrack, update `version`, `url` and `sha256` in `installer/opentrack.json` (the release page shows the
digest). The installer runs the official setup unmodified and silently (`/VERYSILENT`), only when OpenTrack isn't found.
It also:

- adds a firewall rule for `VRTrack.exe` (UDP, any profile, local subnet only; removed on uninstall),
- writes `Documents\opentrack-2.3\VRTrack.ini` and makes it the active profile only if no OpenTrack config exists yet,
- optionally adds a startup entry (`--minimized`).

Code-signing the installer and `VRTrack.exe` (to avoid SmartScreen warnings) isn't set up; add a signing step with your
certificate in `release.yml` if you have one.

## Adding a game profile

Add an entry in `default_profiles()` in `pc/vrtrack/profiles.py` (name + any overrides). Users can also duplicate and
save profiles from the UI; those live in `~/.vrtrack/profiles`.

## Conventions

- Never fake tracking data. The only synthetic output is the explicit, user-triggered *Test OpenTrack output* button.
- Keep camera frames on the device; never write them to disk or the network.
- Keep `protocol.py` and `Protocol.kt` in sync; change the version byte for incompatible changes and update the fixtures.
- LF line endings (`.gitattributes`).
